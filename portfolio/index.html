1. Robot Model & Kinematic Architecture

The demonstration features the Fetch Mobile Manipulator (defined in fetch/fetch.urdf), a mobile manipulation platform designed for unstructured human environments. The robot's kinematic model consists of 26 links and 25 joints:

🦿 Mobile Base & Torso Lift
Differential drive wheels (r_wheel_joint, l_wheel_joint) provide planar mobility. The torso features a high-travel prismatic joint (torso_lift_joint, range 0.0 to 0.386 m) allowing vertical elevation of the entire upper body, head, and manipulator arm.
🦾 7-DOF Manipulator Arm
An articulated 7-axis kinematic arm featuring shoulder_pan_joint, shoulder_lift_joint, upperarm_roll_joint, elbow_flex_joint, forearm_roll_joint, wrist_flex_joint, and wrist_roll_joint, terminating in a parallel-finger gripper.
👀 Pan-Tilt Head Assembly
A 2-axis active sensor head (head_pan_joint, head_tilt_joint) housing RGB-D perception sensors that pan and tilt dynamically to orient the robot's gaze toward active manipulation targets.

Our URDF parser recursively validates every link, joint origin T_origin = Trans(xyz) · Rot(rpy), rotation axis, and joint limit bounds. Visual elements support <box>, <cylinder>, <sphere>, and styled mesh proxies colored by each link's <material> RGBA specification.

2. Finite-State-Machine Choreography

Autonomous motion is orchestrated by the FiniteStateMachine (FSM) component running under make demo. The choreography is defined as a formal state machine in fsm/fetch_dance.json. Each state commands simultaneous multi-joint targets to the /joint_trajectory topic, which are smoothly servoed by JointStatePublisher at 10 Hz. The FSM observes /joint_states and triggers automated on_arrival transitions once all named joints reach their target within tolerance (ε = 0.03).

3. Viewer Architecture & Transform Rendering

The viewer operates as a completely external client decoupled from the graded C++ core runtime, adhering strictly to course protocols:

🔌 Protocol Conformance
The viewer connects to the runtime via the existing raw TCP/JSON gateway (127.0.0.1:9095) using standard newline-delimited JSON. No WebSocket gateways or UI dependencies are introduced into the runtime.
📐 Column-Major Matrix Unpacking
Transforms arrive on /xform_world as 16-element column-major arrays (matrix[4*c + r] = M[r][c]). In Three.js, each link's matrixAutoUpdate = false, and link.matrix.fromArray(matrix) unpacks the exact homogeneous transformation matrix with zero computation overhead.
🔄 Stale Link Object Purge
Whenever a new robot model is loaded through /param_server/set_param, the viewer compares active links against incoming frames, immediately detaching and disposing of old geometry without retaining stale links.

Coordinate conventions are preserved accurately: the viewer configures camera.up.set(0, 0, 1) to natively honor the robotics standard (Z-up, X-forward, Y-left) with a ground grid on the XY plane and an RGB world axis triad.
